# NO 钱包自动化脚本：使用与启动说明

## 1. 项目用途

本项目通过 Playwright 控制 Chrome，通过截图、OCR 和模板识别操作 Flutter/canvas 页面，完成登录后的自动挂单、接单、订单跟踪、超时取消和重新挂单。

脚本只操作配置中允许的页面动作。涉及“确认到账”“放行”等资金安全确认时，会主动拦截，不会盲目点击。

## 2. 首次安装

在项目根目录 `D:\PROJECT\nopay` 打开 PowerShell：

```powershell
uv sync --link-mode=copy
uv sync --extra ocr --link-mode=copy
```

安装后执行环境检查：

```powershell
uv run qjd67-canvas-bot doctor --config configs/qjd67.json
```

至少应看到以下检查通过：

```text
[ok] playwright
[ok] opencv
[ok] rapidocr
```

如果 Playwright 找不到浏览器，可执行：

```powershell
uv run playwright install chromium
```

项目默认使用本机 Chrome 路径，配置在 `configs/qjd67.json` 的 `chrome_path`。

## 3. PushPlus 微信通知准备

1. 在 PushPlus 获取 Token。
2. 将 Token 保存为当前 Windows 用户环境变量：

```powershell
[Environment]::SetEnvironmentVariable('QJD67_PUSHPLUS_TOKEN', '你的PushPlusToken', 'User')
```

3. 关闭并重新启动控制台，让新进程读取 Token。

不要把 Token 写入 JSON、日志或 Git。脚本只在内存中使用 Token，并通过 PushPlus 的 `wechat` 通道提交通知。

当前通知规则：

| 事件 | 标题 | 内容 |
|---|---|---|
| 脚本启动 | 不通知 | 已关闭 |
| 待付款 | `待付款` | `订单已进入待付款状态，请留意买家转账。` |

同一类事件在同一轮运行中只通知一次，避免页面重复识别造成刷屏。PushPlus 返回 `code: 200` 表示已提交成功，微信最终展示仍受 PushPlus 服务和微信限制影响。

## 4. 推荐启动方式：本地控制台

### 4.1 启动控制台

```powershell
uv run qjd67-canvas-bot dashboard --config configs/qjd67.json
```

浏览器访问：

```text
http://127.0.0.1:8765
```

控制台只监听本机地址，不对外网开放。

### 4.2 首次登录

1. 在控制台点击“启动脚本”。
2. 脚本打开独立 Chrome 窗口。
3. 如果出现登录页，在浏览器中手动完成登录。
4. 登录成功进入首页后，不要刷新控制台页面；脚本会继续识别。

登录 Cookie 默认保存在：

```text
.browser-profile/qjd67
```

以后通常不需要重复登录。

### 4.3 设置支付密码

推荐在控制台右侧“支付密码”输入 6 位数字后点击“设置支付密码”。

支付密码只保存在当前控制台进程内存中。脚本检测到支付密码弹窗时，才通过本机受保护接口读取，不写入配置文件、日志或子进程环境变量。

也可以使用环境变量：

```powershell
$env:QJD67_PAY_PASSWORD = '六位数字密码'
```

不要把真实支付密码提交到 Git。

### 4.4 修改参数

控制台可以修改：

- 变现金额、最小限额、最大限额
- 挂单后重挂等待时间
- 页面轮询间隔、操作间隔
- 收款卡片关键词和 OCR 查找次数
- 自动挂单、超时自动重挂、自动接单
- 多挂单和启动后接管已有挂单
- 取消确认等待、挂单二次确认等待、支付密码弹窗超时

修改后点击“保存配置”，再点击“停止脚本”和“启动脚本”，配置才会被运行中的脚本加载。

### 4.5 停止脚本

优先点击控制台右上角“停止脚本”。也可以在启动脚本的终端按 `Ctrl+C`。

停止脚本只停止本项目控制的浏览器自动化进程，不会自动取消平台上的已有订单。

## 5. 命令行启动方式

### 环境检查

```powershell
uv run qjd67-canvas-bot doctor --config configs/qjd67.json
```

### 手动登录

```powershell
uv run qjd67-canvas-bot login --config configs/qjd67.json
```

浏览器打开后手动登录，确认进入首页，再回终端按 Enter 保存登录状态并关闭浏览器。

### 截图和 OCR 调试

```powershell
uv run qjd67-canvas-bot snapshot --config configs/qjd67.json
```

截图和 OCR 框会保存到 `debug-screenshots/`。

### 直接运行自动化循环

```powershell
uv run qjd67-canvas-bot run --config configs/qjd67.json
```

直接运行时，脚本不会提供网页控制台；支付密码应提前配置到环境变量，或使用控制台启动方式以便运行中输入。

## 6. 日常操作流程

```text
启动控制台
  ↓
确认 PushPlus Token 和支付密码状态
  ↓
点击启动脚本
  ↓
确认浏览器已登录并进入首页
  ↓
脚本进入“搬砖”页并自动挂单
  ↓
收到交易通知后自动接单
  ↓
等待买家付款；超时订单按规则取消并补挂
```

开始运行后，优先观察控制台“运行日志”和“调试截图”，不要同时手动操作同一个自动化浏览器页面。

## 7. 常见问题

### 登录后脚本刷新或识别不到

脚本识别到登录/注册页后会等待手动登录，不会主动刷新。确认浏览器确实进入首页后，再观察日志是否出现“导航页”和“搬砖页”。

### 识别不到输入框

脚本会保存 `field_*_not_found.png` 或 `field_*_not_verified.png` 到 `debug-screenshots/`，并暂停本次挂单，不会猜坐标继续提交。检查截图后再调整窗口尺寸、OCR 或关键词。

### PushPlus 没有收到消息

按顺序检查：

1. Token 是否已设置到当前 Windows 用户环境变量。
2. 设置 Token 后是否重启了控制台。
3. 日志是否出现 `[notify] PushPlus 已提交`。
4. 返回值是否包含 `"code":200`。
5. 是否确实识别到了“交易通知”或“待付款”页面。

脚本启动本身不会通知，这是当前设计。

### 出现 `Target page, context or browser has been closed`

说明自动化浏览器或页面已关闭，脚本会停止当前循环。重新点击控制台“启动脚本”即可；已有挂单是否继续跟踪取决于“启动后接管已有挂单”设置。

### 使用系统 Chrome profile 报占用

默认 `browser_profile.mode` 为 `managed`，推荐保持不变。如果改成 `system`，运行前必须关闭所有 Chrome 窗口，因为 Chrome 用户目录不能被两个进程同时使用。

## 8. 日志与调试文件

| 路径 | 用途 |
|---|---|
| `debug-screenshots/dashboard-bot.log` | 控制台启动脚本的运行日志 |
| `debug-screenshots/*.png` | 操作前后截图、OCR 框和失败现场 |
| `dashboard.log` | 控制台进程输出 |
| `dashboard-error.log` | 控制台异常输出 |
| `.browser-profile/qjd67` | 独立 Chrome 登录状态 |

日志和截图可能包含订单、收款方式或页面信息，分享前请先脱敏。
