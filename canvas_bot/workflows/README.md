# `workflows`：跨页面业务流程入口

工作流负责把多个页面上的动作串起来，但不拥有 OCR、浏览器会话或通知实现。当前具体业务方法仍在 `CanvasBot` 中，以降低重构过程中改变交易行为的风险。

## 当前工作流

- `OrderWorkflow.run_move_page`：标记已进入搬砖页，然后执行订单检查、余额判断、挂单/补挂等既有流程。
- `OrderWorkflow.run_withdraw_form`：标记已进入搬砖页，然后执行变现金额、限额、收款卡、确认按钮和后续确认的既有流程。

## 不可改变的流程约束

1. 表单填写后必须经过视觉确认；金额、最小限额、最大限额任一未确认都停止本次挂单。
2. 超时取消遵循先进先出和取消确认等待，不得通过坐标猜测直接确认。
3. 支付密码只在密码弹窗出现后输入，且来源只能是控制台内存。
4. 余额不足时停止新增挂单；余额恢复后才允许补挂。
5. 表单视觉校验失败时，只点击左上角返回搬砖页，再重新读取余额；不得尝试提交当前表单或点击其他确认按钮。
6. 进入表单后必须再次读取页面余额：余额小于原计划但仍满足最小限额时使用“全部”；若低于最小限额则返回等待，不提交无效订单。
7. 配置的变现金额与最大限额相等时，页面最大限额若已自动同步则跳过填写；同步失败仍必须回退到视觉确认后的显式填写。

## 扩展方法

新增跨页面流程时，在这里创建一个小的工作流类或方法，并由 `pages/` 调用。若只是单页显示、日志或导航，不要创建工作流。业务条件、点击实现和视觉校验应继续复用 `CanvasBot` 的已有原子方法，并补充单元测试。
